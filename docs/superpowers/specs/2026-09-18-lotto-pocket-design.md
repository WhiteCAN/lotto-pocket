# 로또 포켓 제품·UX 설계

작성일: 2026-09-18. 사용자가 승인한 대화 요구사항을 구체화한 설계이며, 아래 기본 정책은 구현 시 변경 가능한 초기 결정이다.

## 목적과 범위

이번 주 구매한 자동 용지의 번호를 제외하고 추가로 1~5게임을 만드는 Android 앱. 제외번호 중 과거 출현 빈도가 높은 숫자를 다시 후보로 넣는 옵션을 제공한다. 한 손 조작을 최우선으로 하며, 로그인·서버 없이 로컬 DB에서 추천·통계·당첨 판정을 수행한다. 결과를 예측하거나 확률 상승을 주장하지 않는다. 설명은 앱 정보에 간결하게 두고 매번 경고하지 않는다.

첫 버전: QR, 촬영, 사진 선택, 수동 등록; 인식 검수; 로컬 역대 결과; 1~5게임 추천; 빈도 복원 옵션; 게임별/전체 재생성; 숫자 잠금; 기록; 당첨 판정; 당첨 결과 직접 입력과 데이터 파일 가져오기. 자동 푸시 알림, 계정·클라우드 동기화, 복권 구매·결제는 첫 버전에 포함하지 않는다. 구매기록 및 옵션 JSON 내보내기/가져오기는 데이터 이동을 위한 설정 기능으로 제공한다.

## 플랫폼과 데이터

Kotlin + Jetpack Compose + Material 3, Room(SQLite), CameraX. 최소 Android 8(API 26). QR과 OCR은 앱에 모델을 포함하는 온디바이스 라이브러리를 우선 검증한다. 최초 인식에 네트워크 다운로드가 필요한 구현은 채택하지 않는다. 기본 앱 동작에 INTERNET 권한이 필요 없도록 한다. 라이브러리 버전과 라이선스는 구현 시작 시 공식 문서로 확정한다.

역대 추첨 결과를 검증한 seed DB를 APK에 포함한다. 포함 회차 범위, 마지막 회차, 출처, 검증일을 함께 표시한다. 실제 자료를 확보하기 전 예시 데이터를 역사 데이터처럼 제공하지 않는다. 신규 결과는 수동 입력, 버전이 명시된 JSON 파일 가져오기 또는 앱 업데이트의 추가 seed로 보충한다. 기존 개인 기록을 보존하며 회차 키로 병합한다. 업데이트 시 DB 덮어쓰기 또는 파괴적 마이그레이션을 사용하지 않는다. 온라인 자동 갱신은 확장 가능하지만 필수 의존성은 아니다.

Draw: round(PK), drawDate, numbers(정렬된 6개), bonus, source, verifiedAt.
Ticket: id(UUID), round, source(QR/PHOTO/MANUAL), createdAt.
TicketGame: id, ticketId, line(A~E), numbers.
Recommendation: id, round, createdAt, optionsSnapshot, statisticsThroughRound, sourceTicketIds.
RecommendationGame: id, recommendationId, numbers, lockedNumbers, purchased.
Preferences: gameCount(기본 5), frequencyEnabled(기본 false), frequencyScope(기본 전체), restoreMode, restoreLimit.

추첨 결과는 회차 양수, 유효 날짜, 1~45의 서로 다른 본번호 6개, 본번호에 없는 보너스번호 1개로 검증한다. 같은 회차의 다른 결과를 조용히 덮어쓰지 않고 충돌 내용을 보여준다. 가져오기 크기 제한 5MB, schemaVersion=1, 전체 사전검증 후 트랜잭션 적용. 기록에 원본 사진은 기본 저장하지 않는다.

## 추천 규칙

선택한 동일 회차 용지들의 숫자 합집합 U를 제외한다. 빈도 옵션 OFF: 후보 C = {1..45} - U. ON: C에 복원 집합 R을 더한다.

기본 복원 기준은 전체 1~45 중 출현 빈도 상위 10개와 U의 교집합이다. 대체 옵션은 U 내부에서 빈도가 높은 3개 복원. 상세 설정에서 전체 기준 상위 5/10/15개, 등록번호 기준 1~5개를 고른다. 통계 기간은 전체/최근 100회/최근 50회. 본번호만 집계하고 보너스는 제외한다. 동률은 숫자 오름차순으로 안정적으로 정렬한다. 해당 후보가 없으면 복원 0개를 명시한다.

추천 대상 회차보다 작은 회차의 데이터만 통계에 포함해 미래 정보가 섞이지 않게 한다. 요청한 기간보다 데이터가 적으면 실제 사용한 회차 수를 보여준다. 복원은 후보에 다시 넣는다는 의미이며 고정 또는 가중추첨이 아니다. 최종 후보에서 균등한 비복원 추출로 게임당 6개를 생성한다.

전체 구매 게임과 현재 추천 게임의 완전 동일 조합을 막는다. 직전 게임 재생성 시 직전 조합도 피한다. 숫자 일부 겹침은 허용한다. 각 게임의 잠금은 해당 게임에만 적용한다. 전체 재생성은 모든 잠금을 존중하고 6개 잠금 게임은 건너뛴다. 잠금 해제는 게임별/전체 제공한다. 기존 구매번호나 통계 옵션을 변경할 때 저장 전 초안을 몰래 바꾸지 않고, 새 추천 생성 시 잠금 초기화 여부를 하단 확인창에서 알린다.

후보 6개 미만, 요청 수보다 가능한 조합이 적음, 잠금 때문에 새 조합이 없음은 무한 재시도하지 않고 구체적인 원인과 수정 동작(제외 완화/잠금 해제/게임 수 감소)을 제공한다. 생성 로직은 가능한 조합 수를 먼저 계산하고 반복 횟수를 제한한다. 저장은 연속 탭으로 중복 생성되지 않게 한다.

## 화면과 한 손 조작

하단 탐색: 번호 추천 / 내 로또 / 번호 통계. 주요 CTA는 하단 탐색 바로 위에 고정한다. 상단은 제목, 선택 회차, 상태 표시 중심이다. 화면 하단 시스템 제스처 영역과 키보드 IME inset을 반영한다. 기본 터치 영역 48dp 이상, 본문 16sp, 보조 13sp 이상. 320dp 폭과 큰 글꼴에서 가로 넘침을 허용하지 않는다. 잠금·당첨은 색상 이외 문구와 아이콘으로도 표현한다.

### 번호 추천

빈 상태: 간결한 설명과 하단 큰 '용지 등록하기'. 탭하면 QR 스캔 / 사진 촬영 / 사진 불러오기 / 직접 입력 하단 시트. 카메라 권한은 촬영을 선택할 때 요청하고, 거부 시 사진 선택과 수동 입력을 그대로 제공한다. QR 내용은 텍스트로 파싱하며 임의 URL을 열지 않는다. 실제 용지 포맷의 회차·게임·개수 검증 후에만 등록한다. 비지원 QR은 이유와 다른 입력 방식을 보여준다.

사진은 회차와 A~E 번호 후보를 인식하되 사용자가 확인해야만 저장된다. 인식 신뢰도가 낮거나 개수가 틀린 행을 강조하고 하단 숫자 편집 시트를 연다. 검수 화면 하단 '이 번호로 등록'. 같은 용지 재스캔은 경고하고 중복 제외 처리가 발생하지 않게 한다. 과거 회차 용지는 기록으로 보관할 수 있지만 이번 회차 추천에 자동 포함하지 않는다.

등록 상태: 용지 요약, 제외/복원/최종 후보 개수, 접을 수 있는 번호 상세. 하단 가까이 1~5게임 선택, 빈도 반영 스위치, 상세 옵션, 'N게임 추천받기'. 빈도 상세 옵션은 기본 접힘. 게임 수와 빈도 옵션을 기억한다.

결과: A~E 카드, 번호 6개, 잠금 수, 카드별 '번호 편집'과 '다시 뽑기'. 상단 카드에 손이 닿기 어려운 사용자를 위해 하단 '번호 편집' 진입 후 A~E 선택 칩도 제공한다. 편집 하단 시트는 3열 x 2행의 48dp 이상 번호 버튼으로 잠금을 조작한다. 작은 6개 공 자체를 유일한 편집 타깃으로 쓰지 않는다. 하단에는 '전체 다시 뽑기'와 '추천 저장'. 저장 직후 내 로또로 이동할 수 있다.

### 내 로또

회차별 구매/추천 기록. 실제 구매와 미구매 추천은 명확히 분리한다. 추천에 대해 게임별 구매 표시를 켤 수 있고, 실제 당첨 요약은 구매 기록만 포함한다. 추천 성적은 별도 표기. 최신 회차 결과가 없으면 '결과 미등록'이며 꽝이나 추첨 대기로 단정하지 않는다. 하단 '결과 입력' 및 '용지 등록'. 결과 입력 후 저장된 모든 해당 회차 게임을 즉시 재평가한다. 앱 실행 시 DB에 존재하는 결과로 자동 판정하고, 누락 회차는 외부 연결 없이 조작할 수 있다.

판정: 6일치=1등, 5+보너스=2등, 5=3등, 4=4등, 3=5등, 나머지 미당첨. 일치한 번호 강조. 금액 데이터가 없다면 1~3등 금액을 추측하지 않는다. 추천 기록은 사용한 통계 범위와 옵션 스냅샷을 유지한다.

### 번호 통계

저장된 회차 범위·데이터 출처와 선택 기간을 명시. 빈도 높은 순의 1~45 번호와 출현 횟수. 하단 기간 선택과 데이터 관리 진입. 데이터 관리에서 당첨 결과 입력, 회차 JSON 가져오기, 개인 기록 내보내기/복원을 제공한다. DB가 비었으면 실제 빈도가 없다고 표시한다. 샘플 수치를 실데이터로 표시하지 않는다.

## 시각 방향

밝은 종이색 바탕, 짙은 녹색 CTA, 둥근 카드와 충분한 여백. 어두운 테마도 동일한 정보 계층으로 제공. 번호 공은 구간별 익숙한 색을 사용하되 대비를 확보한다. 카지노·잭팟·수익률 연출은 사용하지 않는다. 추천 결과에는 과한 애니메이션 대신 빠르고 짧은 상태 변화만 적용하고 동작 줄이기 설정을 존중한다. 가칭 '로또 포켓'.

## 검증 및 배포 기준

순수 도메인 테스트: 제외·복원·동률·기간 경계·잠금·중복·불가능 조합·등수 판정. Room 테스트: 앱 업데이트 이후 구매기록 보존, 중복/충돌 가져오기 롤백. UI 테스트: QR 실패 대체 경로, OCR 오류 수정, 1~5게임, 하단 시트, 잠금 유지, 저장 중복 방지. 실제 종이 QR/사진을 통한 인식 정확도와 오프라인 최초 실행 검증은 APK 배포의 필수 조건이다.

검증 화면 크기: 320/360/412dp, 글꼴 1.0/1.3/2.0, 밝음/어두움, 키보드 및 시스템 제스처. TalkBack 라벨과 포커스, 카메라 권한 거부도 확인한다. Gradle 단위 테스트, lint, debug/release APK 빌드, 연결 기기 테스트 후 GitHub Releases APK와 체크섬·변경사항을 제공한다. 서명키는 저장소에 넣지 않고 같은 키로 업데이트를 유지한다.

## 현재 결과물의 한계

인터랙티브 시안은 UX 검토용이다. 임시 메모리와 예시 번호/빈도를 사용한다. 실제 카메라·QR·OCR, Room, 역사 데이터, 파일 가져오기, Android 설치 및 배포 검증은 구현 단계의 작업이다. 시안 완료를 앱 구현 완료로 취급하지 않는다.
